# ADR-008 — حساب حقيقي عبر Supabase Auth + نسخة سحابية بسيطة

**الحالة**: مقبول (قرار المالك 2026-09-04).

## السياق
شاشة الدخول كانت محاكاة محلية (بند 45 من التوجيه: لا وظائف وهمية). المطلوب حساب حقيقي
مع أقل بنية تحتية ممكنة قبل الإطلاق، والمزامنة اللحظية مؤجلة.

## القرار
- **Supabase Auth**: بريد/كلمة مرور + Google + Apple. مفتاح العميل عام (publishable)؛ الحماية في RLS.
- **بوابة مجردة** `AuthGateway` في `lib/core/auth/`: التطبيق لا يعرف المزوّد؛ `NoAuthGateway` عند غياب الإعدادات
  (الاختبارات، البناء بلا أسرار) → وضع زائر محلي كما كان.
- **نسخة سحابية**: جدول `user_backups` صف/مستخدم يحمل JSON الحالة كاملًا، LWW بحسب `updated_at`.
  رفع مؤجّل (3 ث) بعد كل تغيير، وسحب عند الدخول إن كان السحابي أحدث.
- **حذف الحساب** داخل التطبيق عبر `delete_own_account()` (security definer) — شرط المتاجر.
- **الإعدادات** عبر `--dart-define` من GitHub Secrets (`AppConfig`).
- **الروابط العميقة**: `waqti://login-callback/` للهاتف؛ الويب يعود إلى Site URL.

## البدائل المرفوضة
- Firebase Auth: تكلفة تكامل أكبر وبلا Postgres/RLS.
- بناء خادم خاص: صيانة وتكلفة بلا حاجة في هذه المرحلة.
- تخزين الحقول مفصّلة (مزامنة حقلية): مؤجّل لـ ADR-006 عند الحاجة الفعلية.

## العواقب
- سياسة الخصوصية تُحدَّث: بيانات الحساب والنسخة السحابية على خوادم Supabase (EU/ME)، وSentry للأعطال.
- بريد Supabase المدمج مؤقتًا (محدود)؛ يُستبدل بـ Resend + دومين قبل النمو.
- اختبار RLS بمستخدمين حقيقيين هو دليل بوابة Database.
