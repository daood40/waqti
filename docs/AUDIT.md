# AUDIT — الفحص الشامل قبل التحويل الاحترافي

> المرجع: `WAQTI_TRANSFORMATION_DIRECTIVE_v3.md` · التاريخ: 2026-08-28
> المنهج: مراجعة سطرية كاملة لكود `lib/` (~6,800 سطر)، اختبار تفاعلي حقيقي
> في متصفح (كل الشاشات والتدفقات بلقطات موثقة)، وقياسات فعلية لبناء الويب.

---

## 1. Product Audit

**ما هو التطبيق اليوم:** متتبع عادات شهري ممتاز (Habit Grid بأربع حالات)
مع طبقة تحفيز (XP/مستويات/أوسمة) وطبقة اشتراك محاكاة — وليس بعد نظام
إدارة وقت.

اختبار أسئلة فلسفة المنتج على التطبيق الحالي:

| السؤال | هل يجيب اليوم؟ |
|---|---|
| ماذا أفعل الآن؟ | جزئيًا — بطاقة "مهام اليوم" موجودة لكنها ليست مركز الشاشة ولا مرتبة بالأولوية |
| ما التالي؟ | ✗ لا مفهوم وقت داخل اليوم (لا Due Time ولا Time Blocks) |
| ما الذي تأخر؟ | ✗ لا عرض للمتأخرات؛ الأيام الفائتة تُرى فقط بتفحص الشبكة يدويًا |
| ما نسبة إنجازي؟ | ✓ حلقة الإنجاز + شريط اليوم |
| على ماذا أركز؟ | جزئيًا — الأولوية تُخزَّن وتُعرض كشارة لكنها لا تُرتِّب شيئًا |
| كيف كان يومي؟ | جزئيًا — لا Daily Review؛ الإحصائيات شهرية التوجه |
| كيف كان أسبوعي؟ | جزئيًا — أعمدة أسبوعية موجودة، لا Weekly Review |

**الحكم:** الأساس صلب (نموذج بيانات نظيف، حفظ دائم، ثنائية لغة حقيقية)
لكن مركز الجاذبية في الاتجاه الخطأ: الشبكة الشهرية أولًا واليوم ثانيًا.
التحويل يبدأ بقلب هذه الأولوية (Today-first) ثم إضافة بُعد الوقت
(Due date/time → تقويم حقيقي → تذكيرات).

## 2. UX Audit

| الملاحظة | الشدة | القرار |
|---|---|---|
| الرئيسية تفتح على بانر إعلان ثم شبكة الشهر — أول ما يراه المستخدم ليس يومه | عالية | إعادة بناء Home بترتيب: تحية/تاريخ ← اليوم ← المتأخر ← الشبكة (Phase 4) |
| المهام داخل بطاقة اليوم غير مرتبة بالأولوية | عالية | ترتيب Urgent/High أولًا (Phase 4) |
| لا Urgent ضمن الأولويات (المواصفة تطلب 4 مستويات) | متوسطة | إضافة Urgent (Phase 4) |
| المتأخرات غير مرئية إطلاقًا | عالية | شريط "متأخرة" بمعالجة بنقرة (Phase 4) |
| إضافة المهمة سريعة (زر + دائم ← ورقة) لكنها تعرض كل الحقول دفعة واحدة | متوسطة | Progressive Disclosure: أساسي (اسم/أيقونة/تكرار) + "خيارات متقدمة" (Phase 5) |
| بحث الرئيسية يفلتر الاسم فقط بينما تبويب المهام يشمل الوصف | منخفضة | توحيد (Phase 4) |
| أزرار أسهم الشهر ثابتة الاتجاه (chevron LTR) — مقروءة لكن حيادية | منخفضة | تُقبل (متسقة مع اتجاه الزمن في الشبكة) |
| Quick Add لأنواع متعددة (Task/Habit/Event/Note) غير موجود | متوسطة | مع إدخال Events/Notes (Phase 5–6) |
| My Day (Timeline/Blocks) غير موجود | عالية | القرار بعد UX تفصيلي: **Time Blocks** أنسب من Timeline الدقيق لنموذج عادات+مهام (Phase 6) |
| حالات Loading/Empty/Error: Empty ممتازة، لا Loading لأن كل شيء محلي فوري، أخطاء الاستيراد معالجة | منخفضة | تُستكمل مع أي عملية غير فورية مستقبلًا |

## 3. UI Audit

- **الإيجابيات:** التزام كامل بباليتة النموذج المعتمد (فاتح/داكن بقيم hex
  حرفية)، Tajawal مضمّن، بطاقات هادئة بظلال خفيفة، RTL/LTR متناظران فعليًا
  (موثق بلقطات)، Dark Mode حقيقي وليس فلترًا.
- **الملاحظات:** لا يوجد Urgent لونيًا؛ التمييز البصري للمتأخر غير موجود؛
  كثافة البطاقات في الإحصائيات مقبولة لكن قابلة للتخفيف؛ الرسوم المتحركة
  قليلة وهادفة (مطابقة لروح "Calm").
- **الحكم:** اللغة البصرية سليمة ومطابقة للمرجع؛ التحسين المطلوب دلالي
  (أولويات/تأخر) لا جمالي.

## 4. Technical Audit

- **التقنية:** Flutter 3.35.1 (Android/iOS/Web) — قرار مثبت (ADR-001)؛
  بند "React/Next.js" في التوجيه يُفسَّر بـ"التقنية المستخدمة" = Flutter.
- **الاعتماديات:** 3 فقط (provider, shared_preferences, cupertino_icons) —
  سطح تبعيات ممتاز، لا مخاطر سلاسل توريد تُذكر.
- **الجودة الآن:** `dart format` نظيف، `flutter analyze` صفر ملاحظات،
  27 اختبارًا خضراء، CI أخضر (8/8 منذ التحويل) ببناء APK ونشر Pages مع كل push.
- **نقاط قوة:** فهرسة الحالات بتاريخ كامل، حسابات تاريخ آمنة من DST
  (أُصلحت هذه الجلسة)، CanvasKit مستضاف ذاتيًا (يعمل دون CDN).
- **نقاط ضعف:** `AppState` مركزي واحد (مقبول الآن، عنق زجاجة لاحقًا)؛
  التخزين JSON واحد في shared_preferences (لا استعلامات/فهرسة/FTS).

## 5. Architecture Audit

الحالي: `models / state / screens / widgets` بسيط ونظيف. الفجوة مقابل
الهدف (ADR-002/003): لا طبقة Repository، لا فصل Feature-based، الحالة
كلها في ChangeNotifier واحد. **القرار قائم ولم يتغير:** انتقال تدريجي
Drift + Riverpod + features/ بأصغر خطوات تُبقي التطبيق أخضر
(تفاصيل المسار في `ARCHITECTURE.md` §3) — يبدأ فعليًا مع Phase 5
لأن نموذج المهام الجديد (تواريخ/مهام فرعية/وسوم) يستحق قاعدة SQLite
بدل توسيع JSON.

## 6. Data Model Audit

| الكيان المطلوب (v3) | الحالة |
|---|---|
| Tasks (title/desc/priority/category/repeat/notes/status/timestamps) | ✓ جزئيًا — **ناقص:** dueDate/dueTime/tags/subtasks/reminder/createdAt/updatedAt |
| Priority بأربعة مستويات | ✗ ثلاثة — تُضاف Urgent |
| Subtasks | ✗ |
| Habits ككيان مستقل عن Tasks | ✗ موحّدان (مقصود في النموذج الأولي) — يُفصلان مع Drift |
| Habit Logs بتاريخ كامل | ✓ (statuses) |
| Events / Reminders / Notes / Tags | ✗ غير موجودة |
| Categories | ✓ |
| Sync State | ✗ (مرحلة المزامنة) |

فهرسة الحالات بمفتاح `yyyy-MM-dd` قرار سليم يسهّل الترحيل إلى Drift.

## 7. Security Audit

- لا خادم ولا شبكة إطلاقًا في نسخة اليوم ⇒ سطح الهجوم شبه معدوم؛
  لا أسرار في الكود (فُحص)؛ المصادقة محاكاة معلنة.
- البيانات محلية في shared_preferences غير مشفرة — مقبول لبيانات مهام،
  ويُرقّى بـ SQLCipher اختياريًا مع Drift (مثبت في v2 §30).
- الاستيراد يمر بـ `jsonDecode` مع أنواع مفحوصة و`try/catch` — لا حقن.
- Export/Clear موجودان (تصدير JSON + تسجيل خروج يمسح)؛ Delete Account
  يأتي مع المصادقة الحقيقية (Phase 14).
- **إجراء فوري:** لا شيء حارق. **عند المزامنة:** RLS + تشفير نقل/سكون
  حسب `SYNC.md`.

## 8. Performance Audit (قياسات فعلية)

| القياس | القيمة | الحكم |
|---|---|---|
| main.dart.js | 3.2MB (قبل ضغط النقل) | طبيعي لـ Flutter Web؛ يُحمَّل مرة ثم يُخدم من Service Worker |
| canvaskit.wasm | 6.8MB (يُحمَّل المتغير المطلوب فقط) | كلفة أول زيارة معروفة؛ Offline بعد ذلك |
| تفاعلات الواجهة | فورية (بيانات محلية، لا شبكة) | ✓ |
| الشبكة الشهرية | O(المهام × 7) لكل إطار عرض | ✓ |
| الإحصائيات | O(المهام × أيام الشهر) عند كل بناء | مقبول الآن؛ مع Drift تصبح استعلامات مفهرسة |
| خريطة السنة | ترسم 365 خلية في CustomPainter واحد | ✓ سريعة |

أهداف v2 §31 (فتح < 1.5s على الجوال الأصلي، إضافة < 100ms) قابلة للتحقيق؛
عنق الزجاجة الوحيد هو أول تحميل ويب (سمة منصة وليست تصميمًا).

## 11. Skills Found

قوائم الـ Skills المتاحة في بيئة العمل وُجد أنها موجهة لمنصة الويب/JS
(css-*, javascript-*, typescript-*, react-oriented web-*) أو للبنية
التحتية (kubernetes-*, terraform-*) — **لا يوجد Skill مخصص لـ Flutter
أو لتطبيقات الإنتاجية** ضمن المتاح.

## 12. Skills Used

فُعّلت **مبادئ** الملائم منها يدويًا حيث تنطبق على مخرجات الويب:
`responsive-design` (تخطيطات مرنة)، `web-accessibility` (Semantics
وTouch targets في المكونات)، `service-workers` (كاش Flutter SW القائم)،
`web-performance` (استضافة CanvasKit ذاتيًا)، `dataviz` (رسوم تُجيب عن
سؤال واحد لكل رسم). لم تُستدع Skills لا تنطبق على Flutter لتجنب ضجيج
لا يخدم المشروع.

## 13. Proposed Architecture

كما في `ARCHITECTURE.md` §2–3 (Drift مصدر حقيقة + Riverpod + features/
+ Repository)، مع إضافة v3: كيانات Events/Notes/Reminders/Subtasks/Tags
في مخطط Drift من اليوم الأول، ووحدة `today/` تُغذّي الـ Dashboard
باستعلام واحد مجمّع.

## 14. Design System

القائم: `WaqtiColors` (ThemeExtension، فاتح/داكن كاملان) + Tajawal
(4 أوزان) + مكونات موحدة (WqCard, WqChip, WqIconButton, SegmentedPills,
StatusDot, LevelBar, CompletionRing, StatCard, EmptyHint, SectionTitle).
**التوسيع المقرر (Phase 2):** رموز مسافات 4pt مسماة، سلم Typography
مسمى، ولون دلالي للأولوية Urgent — دون المساس بالباليتة المعتمدة.

## 16. Testing Plan

- **الآن:** 27 اختبار وحدة/واجهة خضراء + فحص تفاعلي متصفحي يدوي موثق.
- **كل مرحلة تضيف:** وحدات لمنطقها (فرز الأولويات، المتأخرات، حدود
  الشهور، TZ)، Widget tests للشاشة المعدلة، وسيناريو E2E متصفحي
  (Playwright ضد بناء الويب) للتدفق الرئيس.
- **إلزاميات v2 §35 تبقى:** Recurrence/RRULE، Streak rules، Sync
  conflicts، Notifications، استمرارية المؤقت.

## 18. Definition of Done (لهذا التحويل)

كل مرحلة تُقفل فقط إذا: CI أخضر (format/analyze/tests/builds) ·
مفحوصة RTL+LTR وفاتح+داكن بلقطات · تعمل دون إنترنت · لا بيانات وهمية ·
لكل ميزة Empty/Error/Confirmation/Undo حيث يلزم · الشاشة تجيب أسئلة
قاعدة UX الثلاثة · موثقة في `PROJECT_STATUS.md`. والمنتج النهائي يحقق
معايير v3: Professional, Fast, Simple, Stable, Scalable, Beautiful,
Reliable.
